# CLAUDE.md — Обязательные правила работы с проектом iorg

## 1. Назначение и стек проекта
- Проект **iorg** — нативная 2D-игра на движке **Godot 4.6.x** (GDScript), ориентированная на **ПК (Windows/Linux/macOS)** и **Android (APK)** в **горизонтальной (Landscape)** ориентации.
- **Разрешено**: Godot 4.x, GDScript (`.gd`), сцены (`.tscn`), ресурсы (`.tres`), конфигурация (`project.godot`), встроенные ноды и классы движка, оффлайн-ассеты в `res://assets/` (`.png`, `.svg`, `.ogg`, `.wav`, `.ttf`/`.otf`, `.glb`/`.gltf`).
- **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО**:
  - React, React Native, Next.js, Vue, Svelte, Angular, Solid, Preact и любые JS-фреймворки.
  - HTML, CSS, JavaScript, TypeScript, JSX, TSX.
  - `package.json`, `node_modules`, `vite.config`, `webpack`, `rollup`, `esbuild`, `bun`, `deno`, `pnpm`, `yarn`.
  - Electron, Tauri, Capacitor, Cordova, Ionic, Flutter.
  - Firebase, Supabase, Vercel, Netlify, Google AI Studio Build и любые облачные хостинги/бэкенды.
  - Web-версии, PWA, Service Worker, `manifest.json`, браузерные сборки.
  - Python/Node.js/Go/Rust-серверы, Docker, CI/CD для веба.

> **Правило проверки перед каждым изменением / коммитом**:
> *«Запустится ли это через `godot --path .` без браузера и интернета?»*
> Если нет — немедленно переделать.

## 2. Обязательный рабочий процесс (Workflow)
1. **Сверка с `ROADMAP.md`**: Перед поиском или созданием любого файла всегда сначала открывай `ROADMAP.md`. Запрещено создавать дублирующие скрипты/сцены или искать файлы вслепую, если путь уже есть в карте.
2. **Проверка `TZ.md`**:
   - `TZ.md` — файл задач и критических ограничений от пользователя.
   - Никогда не перезаписывай и не удаляй правила пользователя в `TZ.md`.
   - Если в `TZ.md` добавлены новые задачи — выполняй их приоритетно; если в файле только базовые правила или он пуст — пропускай этап чтения новых задач.
3. **Обновление документации после каждой задачи**:
   - Добавил/переименовал/удалил файл -> обнови `ROADMAP.md`.
   - Завершил фичу/фикс/изменение -> добавь запись в `CHANGELOG.md` (формат *Keep a Changelog*).

## 3. Стандарты кода GDScript (Godot 4.6.x)
- **Именование**:
  - Файлы и папки: `snake_case` (`game_arena.gd`, `player_config.tres`).
  - Классы (`class_name`): `PascalCase` (`class_name PlayerConfig`).
  - Переменные, функции, сигналы: `snake_case` (`move_speed`, `_on_orb_collected()`).
  - Приватные члены: префикс `_` (`_velocity`, `_dash_cooldown_timer`).
  - Константы и Enum: `UPPER_SNAKE_CASE` (`SAVE_VERSION`, `TouchMode.AUTO`).
- **Типизация**:
  - Всегда указывай статические типы для переменных, параметров и возвращаемых значений функций (`var score: int = 0`, `func get_save_path() -> String:`).
  - Используй `@export` для параметров инспектора и `@onready` для ссылок на дочерние ноды.
- **Архитектура и данные**:
  - Не хардкодить баланс (скорость, урон, тайминги, размеры волн/арен) в скриптах — выносить в `Resource`-классы (`.tres`) внутри `res://resources/`.
  - Сцены собирать из нод в `.tscn`, не создавать сложную иерархию нод процедурно в коде без реальной необходимости (например, пулы/инстансирование динамических объектов).
  - Для связи между несвязанными системами использовать сигналы `EventBus` вместо жёстких `get_node("/root/...")` связей.
  - Комментарии и doc-комментарии (`##`) писать кратко и по делу для публичных API и неочевидной логики.

## 4. Кроссплатформенность (ПК + Android)
- **Экран и UI**:
  - Базовое разрешение `1280x720`, `stretch/mode = canvas_items`, `stretch/aspect = expand`, ориентация `landscape`.
  - Весь UI строить только на `Control`-нодах с якорями (`Anchors`) и `MarginContainer`, чтобы интерфейс корректно адаптировался под соотношения сторон от 16:9 (ПК) до 20:9 (телефоны).
- **Ввод**:
  - Действия описываются в `InputMap` (`project.godot`).
  - Сенсорное управление отображается автоматически при `DisplayServer.is_touchscreen_available()` или при ручном выборе `always_on` в настройках.
- **Сохранения**:
  - Только локально в `user://` через `FileAccess` (JSON с `save_version`) и `ConfigFile` (`user://settings.cfg`).
